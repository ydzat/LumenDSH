## 4. 可行路径组合

- **路径 A（插件优先，推荐）**：F1 → F2 → {M2, M3, M6} → F5 → F9。
  先把官方页面扩展点做出来，再撤原生覆盖，最后验证自主闭环。
- **路径 B（清理优先）**：M1 → M5 → M4 → 卡住：M2/M3/M6 仍需 F2，且删掉原生按钮后
  没有插件接管导航。**不可单独完成目标。**
- **路径 C（自主优先）**：F4 → F5？F5 依赖 F1/F2，无法先跑。**不可行。**
- **并行补充**：F6（重启恢复）、F7（状态源）、M1（删原生对话）与路径 A 无冲突，
  可穿插进行；F4 在 F5 前完成即可。

**结论**：正确顺序是 **A 为骨架，B 的 M1/M5 作为并行清理，C 放到 F5 之后**。
关键路径：`F1 → F2 → F5 → F9`，迁移债中 M2/M3/M6 是 F2 的下游，M1/M5/M4 是独立清理支线。

## 5. 依赖关系里容易搞错的三点

1. **M2 不能先做**：删掉 ⌂/🎤 之前必须有 F3（返回）与 F2（语音注入），否则用户失去入口。
2. **M1 可以先做**：它只删原生对话 UI，不依赖插件；语音发送仍走原生路径。
3. **F5 不是纯技术任务**：它需要一个真实的自主轮，循环恢复是用户决定；没有它 M10 只能算"地基零件齐了"，不算"地基可用"。

## 7. 真机走查记录（2026-10-27）

从桌面打开 app → 首页 → 抽屉 → 官方界面，逐步操作后的发现（截图在
`~/tmp/walk1..4.png`，仅本机）：

### 7.1 首页（MainActivity）

- 首页已经包含一段**对话消息摘录**（最后几条消息 + 工具调用），与官方会话重复，
  而且它的"工具运行中"可能滞后于真实状态。
- 状态行"LOCAL · 本机已连接"与官方页面顶部状态是两套渲染，此前还出现过
  "本机连接中断"而 WebUI 正常的情况。

### 7.2 抽屉

- 「会话 / 任务与收件箱 / 记忆 / 展开当前对话」四项与官方页面（会话、自动化任务、
  记忆、composer）重复；其中"任务与收件箱"还把官方 automation 和原生分享弹窗混在一起。
- 「交互与声音」一半是 app-only（唤醒、声纹、提供商），一半与官方语音设置重复。
- 「行为与自主活动」里有两个语义重叠的控件：**"自主活动"开关**（关=停止安排新的活动）
  与**"恢复自主活动"行**（显示已暂停）。当前开关是开、行却显示暂停，用户无法判断真实状态。
- 应保留的原生入口：角色与空间、行为与自主活动、通知与后台、连接与系统、
  屏幕读取权限、官方界面；其余迁移或删除。

### 7.3 官方界面（WebChatActivity）

- 右上角有**两个原生覆盖按钮**（⌂ 返回、🎤 语音），不属于官方 UI，也不是插件；
  其中 🎤 与官方 composer 自带的麦克风**功能重复**。
- 顶部 **tide 胶囊与官方顶栏文字重叠**：「梁文谷 · 6:16:03」压在
  「4 个后台任务 / 今日 ¥0.49 / 设置图标」上，属于布局缺陷。
- 官方 UI 是桌面布局：左侧图标栏在手机上偏小，顶栏信息拥挤。
- composer 自带麦克风（官方实验插件）在本地不可用，但按钮仍存在，形成"能点但失败"的
  误导性 affordance。

### 7.4 对任务图的影响

- M2 明确为"撤掉 ⌂/🎤 覆盖按钮"，依赖 F2（语音注入）与 F3（返回/导航）；
  在它们可用前不能删。
- 新增 **F10 胶囊/顶栏布局修复**（tide 胶囊与官方顶栏碰撞），独立于 F1，可并行。
- 新增 **M7 修复自主活动双控状态**（开关与恢复行合并为单一状态控件），依赖 M5/M4
  的抽屉整理，或作为 M4 的一部分。
- M1 的范围扩大：删除首页消息摘录与"展开当前对话"，不只是删 transcript 页。
- "工具运行中"状态需要单一来源（并入 F7）。


## 8. F5 自升级闭环的入口（2026-10-27）

自主开发轮的 bash 白名单只允许 `git`、`node tooling/`、`bash tooling/` 等仓库命令，
不允许直接跑 `integrations/supervisor/*` 或任意 HOME 脚本。为了让自主轮能完成
"构建 → 安装 → 重启"：

1. `bash tooling/android-build/build.sh` 已在白名单内，负责构建；
2. `phone_install` 工具（adb）负责静默安装；
3. 新增 `tooling/self-restart.sh`：写续跑标记、延迟 20 秒在轮次结束后重启 host；
   因为它是 `bash tooling/` 命令，自主轮可以调用。

重启后的续跑由宿主消费标记完成；中断的自主轮按既有 at-most-once 规则不重放，
下一次唤醒提前。下一步需要一次真实的自主轮来验证这条链路。
