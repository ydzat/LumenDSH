# Assistant Package Contract v0.1

Status: composition and import strategy accepted; external format revisions must be pinned during M4.

## Package types

- `appearance`: images/animations and semantic state mappings.
- `voice-profile`: installed STT/TTS provider references and parameters; no credentials.
- `behavior-profile`: explicit agent-style and interaction preferences; application to DSH requires a verified adapter capability.
- `assistant-profile`: references exact versions of the above components.

Loading appearance assets must not change the session, model, persona, or tool permissions. Voice profiles reference installed engines; they are not native engine installers. There is no initial general-purpose script executor in a resource package.

## Manifest vocabulary

Initial manifests are UTF-8 JSON inside a ZIP distribution. A formal JSON Schema and executable validators are M4 deliverables; do not treat this table as an implemented parser.

| Field | Meaning |
| --- | --- |
| `schemaVersion` | Manifest contract version; reject unsupported versions |
| `id`, `version`, `kind` | Stable package ID, semantic version, and type |
| `displayName`, `author`, `license`, `source` | Human identity and source/asset attribution |
| `requires` | Minimum host/renderer version and required capabilities |
| `files` | Relative path, byte length, and SHA-256 for each payload file |
| `entry` | Type-specific configuration path |
| `components` | Exact component references for an assistant profile |

Hashes establish integrity relative to the manifest, not publisher authenticity. Authenticated import/release provenance is handled by the update module.

Reject absolute paths, traversal, escaping symlinks, duplicate normalized paths, oversized expansion, and undeclared executable content. Keep original upstream provenance and do not redistribute character assets merely because code is open source.

## Import compatibility

First candidate: Codex-compatible `pet.json` plus sprite sheets, using [ysyyhhh/dsh-pet](https://github.com/ysyyhhh/dsh-pet) as an implementation reference. Second candidate: the video-animation format of [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet).

Compatibility is a matrix of source project, pinned format/revision, supported fields, renderer behavior, and known omissions. Do not advertise universal OpenAI/DSH pet compatibility. Preserve external manifests as provenance and normalize through an importer rather than forcing upstream packages to adopt our format.

Normalized appearance states: `idle`, `listening`, `thinking`, `working`, `speaking`, `waiting`, `error`. Missing animations map to a declared fallback, ultimately a built-in static placeholder. Voice and tool states do not require an LLM call to select animation. A renderer maps audio activity to mouth animation only if the format supports it.

## Storage and composition

Install immutable versions side by side. Keep active pointers and user overrides outside package payloads. A composite profile activates only after all referenced components validate; partial failure leaves the old profile active. Switching skins preserves conversation and voice ownership.

Versioned release metadata belongs in Git; downloaded packs, recordings, and private voice reference material do not. Rendering fixtures used for tests must have explicit redistribution rights.

## Implemented v2 appearance adapter (M4 increment)

The appearance-only external ZIP adapter and renderer are implemented; see
[the exact accepted subset and bounds](../design/m4-pet-format.md). The generated
[normalized record schema](../schemas/appearance-v1.schema.json) uses the source ZIP
SHA-256 as its immutable version. It records file lengths/digests, source manifest,
notices and an explicit `codex-pet-v2` renderer requirement. It is generated by the
adapter, not accepted as an arbitrary external executable package.

User-selected import is inert until explicit activation. Image decoding and integrity
checks precede pointer replacement. Appearance switching has no access to DSH identity,
voice-profile configuration or tool permissions. The appearance-only subset is verified. Local appearance/voice composition records
and their atomic activation are now implemented separately; see
[profile design](../design/m4-profiles.md) and [P03 evidence](../../tests/m4-profile-evidence.md).
Local behavior policies and external composition JSON import are implemented in M7; see the current contracts below.

The behavior statement above is superseded for local configuration by the M7
[behavior policy contract](../m7-behavior-policy.md) and
[schema](../schemas/behavior-v1.schema.json). The authenticated DSH adapter owns
immutable versions, activation/readback and recovery; Android edits it independently
of skin/voice and synchronizes the current name/session. This is a native host
configuration, not an external executable ZIP installer. External composition JSON import reuses the existing schema and installed component references, bounded to 8 KiB with strict UTF-8, a preview and explicit atomic activation. It does not bundle or download appearance archives, TTS engines or executable payloads.

## M4.5 presentation settings increment

Schema version 1 local presentation settings are stored separately from appearance
and voice profiles. This increment supports name/tag, bounded size, colors, bubble
lifetime and up to 20 preset phrases. A native form edits name/tag/size/lifetime/phrases;
invalid input is rejected before committing. Existing profiles need no pointer change.
Preset text is labeled as preset content and does not submit a model request.
External settings import and content-kind scheduling are implemented in the extensions below.
Authenticated release packaging remains M5 work.

### Presentation import/history extension (0.4.21)

Version 1 gains optional `animationSpeed` (0.5..1.5, default 1 relative to the existing
slowed renderer) and `phraseWeights` (one integer 1..100 per phrase, default 1).
Unknown fields reject. The 8 KiB limit counts UTF-8 bytes. Weights affect preset
selection only and never replace source priority or fabricate memory content.

JSON document import validates UTF-8, size and schema before a human-readable preview;
only Apply changes settings. Export uses Android's explicit destination picker.
Saving archives both previous and new valid JSON as SHA-256-named immutable local
versions before atomically committing the active preferences. History can preview
and reapply an old version; tampering rejects. This is local configuration history,
not authenticated M5 release/rollback machinery. Profile/appearance/voice/session
pointers remain separate. Overlay appearance follows the same size/colors/pacing.

### Source-aware presentation extension (0.4.24)

`AttentionQueue.Source` identifies `reply`, `preset`, `task`, `notification` and
reserved `memory`. Replies carry server event sequence; other entries require a
source reference. Pending items reconcile within their source/reference; reply
sequence deduplication remains unchanged. Presets and notification excerpts retain
visible source labels in collapsed and expanded views. Memory has no producer yet.

Optional `contentWeights` maps these keys to integers 1..100, defaulting to
4/1/2/2/1. The settings UI, import/export and immutable history preserve this field.
Unknown keys reject. Smooth weighted selection chooses only among waiting sources,
with FIFO within a source; it never preempts the current item. Reading, decisions,
voice and spatial admission continue to control attention. Weights do not schedule
backend tasks or change how often the Agent speaks. Public task traces stay behind
the character; the explicit task-details action uses the foreground queue. Opening
an archived completion in its original conversation queues a labeled notification
excerpt. Neither path submits a prompt or invents memory/reasoning events.


## Foreground narration correction (0.4.25)

The user rejected the floating capsule as the default. Follow the latest
[unboxed narration decision](../design/m4-attention.md): ordinary text reveals below the whole character,
above the controls, in a separate layout region. Existing source/queue/reading
ownership remains; no opaque floating surface or character overlap. This supersedes
the earlier default capsule placement requirement. F13 remains open for user review.

### Conversation and gesture revision (0.4.26)

The latest user revision replaces default foreground source scheduling with a
chronological compact conversation and Expand action. `holdSeconds` controls idle
hiding. Legacy `phrases`, `phraseWeights`, and `contentWeights` remain parseable and
preserved in existing files, but have no preset producer or conversation reordering
role. Gesture zoom is a local view preference, independent of imported sprite data.
See the current conversation/gesture section in `docs/design/m4-attention.md`.

### Foreground height refinement (0.4.27)

The conversation region is now a foreground sibling above the character/layout
content. Its upper edge follows the scaled feet through unused scene space while
its lower edge stays above voice controls. This replaces the fixed 140 dp visible
height; that value remains only a layout reservation. Fade and conversation ownership
are unchanged. See the latest section of `docs/design/m4-attention.md`.
